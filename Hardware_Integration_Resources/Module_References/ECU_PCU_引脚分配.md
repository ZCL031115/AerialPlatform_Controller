# ECU 与 PCU 引脚分配

本文整理自现有急停工程、高空车测试工程，以及已确认的局部原理图。MCU 为 STM32F103ZE。

## 1. 角色定义

| 单元 | 安装位置/职责 | 关键功能 |
|---|---|---|
| PCU | 地面侧安全控制单元 | 急停回路输入、LoRa 发令、UWB（高空车测试工程）、控制数据转发 |
| ECU | 高空车车载执行单元 | LoRa 收令、NFC/RC522 授权、安全继电器控制、姿态/环境传感器 |

## 2. 两端共用引脚

| MCU 引脚 | 外设/功能 | 信号方向 | 说明 |
|---|---|---|---|
| PA9 | USART1_TX | MCU -> 外部 | 调试/串口 1 发送 |
| PA10 | USART1_RX | 外部 -> MCU | 调试/串口 1 接收 |
| PA2 | USART2_TX | MCU -> 外部 | 串口 2 发送；若该板装有 SP3232，则经其转换为 RS-232 电平 |
| PA3 | USART2_RX | 外部 -> MCU | 串口 2 接收；若该板装有 SP3232，则由其从 RS-232 电平转换回来 |
| PB10 | USART3_TX | MCU -> LoRa RX | LoRa 模块本地 UART 发送 |
| PB11 | USART3_RX | LoRa TX -> MCU | LoRa 模块本地 UART 接收 |
| PE0 | LoRa MD0 | MCU -> LoRa | LoRa 工作模式控制 |
| PE1 | LoRa MD1 | MCU -> LoRa | LoRa 工作模式控制 |
| PB6 | BMP280 SCL | 双向 | 原工程使用 GPIO 模拟 I2C；HAL 可改用 I2C1_SCL |
| PB7 | BMP280 SDA | 双向 | 原工程使用 GPIO 模拟 I2C；HAL 可改用 I2C1_SDA |
| PA0 | KEY1 | 外部 -> MCU | 板载按键 1 |
| PC13 | KEY2 | 外部 -> MCU | 板载按键 2 |

### LoRa 模式脚

| 模式 | PE0 / MD0 | PE1 / MD1 | 用途 |
|---|---:|---:|---|
| 正常收发 | 0 | 0 | LoRa 透明传输 |
| 配置/休眠 | 1 | 1 | 以手册规定的 UART 参数读写模块配置 |

LoRa 的 AUX 未接入 MCU。模式切换、发送完成和参数写入必须按模块手册使用保守延时，不能依赖 AUX 判定忙闲。

## 3. ECU 专用引脚

| MCU 引脚 | 外设/功能 | 信号方向 | 当前软件含义 |
|---|---|---|---|
| PD6 | 安全继电器控制 | MCU -> 继电器驱动 | 程序初始化为高；收到急停后输出低。继电器触点的实际断开/吸合极性仍应以继电器驱动原理图为准。 |
| PA4 | RC522 SDA/SS | MCU -> RC522 | RC522 片选 |
| PB8 | RC522 RST | MCU -> RC522 | RC522 复位 |
| PB13 | RC522 SCK / SPI2_SCK | MCU -> RC522 | 原工程 GPIO 模拟 SPI；HAL 可迁移为 SPI2 时钟 |
| PB14 | RC522 MISO / SPI2_MISO | RC522 -> MCU | 原工程 GPIO 模拟 SPI；HAL 可迁移为 SPI2 MISO |
| PB15 | RC522 MOSI / SPI2_MOSI | MCU -> RC522 | 原工程 GPIO 模拟 SPI；HAL 可迁移为 SPI2 MOSI |
| PA11 | ADXL345 SCL | 双向 | GPIO 模拟 I2C 时钟；与 USB/CAN1 默认复用冲突 |
| PA12 | ADXL345 SDA | 双向 | GPIO 模拟 I2C 数据；与 USB/CAN1 默认复用冲突 |

## 4. PCU 专用引脚

| MCU 引脚 | 外设/功能 | 信号方向 | 当前软件含义 |
|---|---|---|---|
| PD6 | 急停回路状态 | 外部 -> MCU | EL817 光耦输出；低电平表示 VIN2 存在/回路正常，高电平表示 VIN2 丢失/急停。 |
| PC10 | UART4_TX | MCU -> UWB | 仅高空车测试工程的 UWB 串口 |
| PC11 | UART4_RX | UWB -> MCU | 仅高空车测试工程的 UWB 串口 |

### PCU 急停输入电路（VIN2 - EL817 - PD6）

| VIN2 状态 | EL817 输出晶体管 | PD6 电平 | PCU 动作 |
|---|---|---:|---|
| VIN2 正常存在 | 导通 | 低 | 正常；此前若处于急停状态则发送 `0x26` 恢复命令 |
| VIN2 消失、急停按钮断开或线路断线 | 截止 | 高（R54 10 kOhm 上拉） | 发送 `0x87` 急停命令 |

输入侧由 R53（1 kOhm）限制 EL817 LED 电流，输出侧由 R54（10 kOhm）上拉至 3.3 V。因此 PD6 虽在旧代码中配置为浮空输入，硬件上实际已有外部上拉，电平不会悬空。

注意：局部原理图两侧均标注 `GND`。若两者属于同一电源网络，EL817 不构成完整的电气隔离，仅提供输入电平转换和一定的抗干扰/保护作用。

## 5. 急停命令与执行链路

```text
PCU 急停回路断开
  -> VIN2 消失，PD6 由 R54 上拉为高
  -> PCU USART3 / LoRa 发送 0x87
  -> ECU USART3 / LoRa 接收 0x87
  -> ECU PD6 输出低
  -> 继电器释放，切断外部设备的控制或使能回路
```

| 命令字节 | PCU 来源 | ECU 当前处理 |
|---:|---|---|
| `0x87` | PCU PD6 读高（急停） | 将 ECU 继电器控制脚 PD6 拉低 |
| `0x26` | PCU PD6 从高恢复到低 | 将 ECU 继电器控制脚 PD6 拉高并恢复通信状态 |
| `0x86` | PCU KEY2 | ECU 置通信断开标志；现有工程中继电器断开语句被注释，不能视为急停保护。 |

急停并不会让 ECU MCU 停机；ECU 需要持续运行，才能保持安全状态并接收后续的人工复位/恢复流程。

## 6. HAL 迁移建议

| 功能 | HAL 外设/模式 |
|---|---|
| LoRa | USART3：PB10/PB11；PE0/PE1 为 GPIO 推挽输出 |
| PCU 急停 | PD6 为 GPIO 输入；使用外部 R54 上拉，GPIO 可配置为 `GPIO_NOPULL` |
| ECU 继电器 | PD6 为 GPIO 推挽输出；上电默认状态应按继电器驱动电路验证，安全设计建议默认保持断开 |
| BMP280 | 优先 I2C1：PB6/PB7 |
| RC522 | 优先 SPI2：PB13/PB14/PB15，另保留 PA4 片选、PB8 复位 |
| ADXL345 | 保留 PA11/PA12 GPIO 模拟 I2C，或改线并与 BMP280 共用 I2C1 |
| UWB | UART4：PC10/PC11（PCU 高空车功能） |

## 7. 整合工程必须保留的安全约束

1. 急停状态应锁存；按钮释放不应直接自动吸合 ECU 继电器，应要求明确人工复位及全部安全条件满足。
2. ECU 应监测 PCU 的 LoRa 心跳超时。PCU 掉电或无线链路丢失时，ECU 应释放继电器。
3. LoRa 急停命令应升级为带帧头、地址、序号、CRC、重复发送和确认的协议，不能只依赖单字节匹配。
4. ECU 继电器输出的真实安全极性必须结合继电器驱动与触点原理图、万用表实测确认后再固化。
